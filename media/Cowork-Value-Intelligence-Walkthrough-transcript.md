# Cowork Value Intelligence walkthrough transcript

The template contains no embedded data and is designed to load approved customer exports.

## Cowork Value Intelligence

Meet Cowork Value Intelligence. This data-free Power BI template connects observed Cowork activity with transparent value assumptions, customer-priced consumption, and evidence-aware recommendations. It comes to life with your approved customer exports. Here is a guided tour of the decisions it supports and the boundaries that keep those decisions defensible.

## Start Here

Start Here is the report's decision map. It routes leaders to value, cost, methodology, data connection, business-unit, and user-tier questions. Begin with the decision you need to make, then confirm that the page's required source files and customer inputs are available.

## Executive Summary

The Executive Summary starts with observed active users and task volume, then adds modeled value, effective platform cost, and return under the selected assumptions. Reconciliation and completeness indicators remain visible. Treat the result as scenario-based decision support, not causality, audited savings, or realized cash return.

## Task Categories & Methodology

Task Categories and Methodology explains what people delegate and how that work becomes modeled value. Task volume, scheduled share, and mapping coverage are observed or derived from source records. Minutes saved are published assumptions applied to each category, not measured task duration.

## Methodology & Value Calculator

The Methodology and Value Calculator keeps every major assumption visible. Compare baseline and adjusted value, inspect category sensitivity, and record the selected labor rate, estimate basis, billing mode, and price inputs. The hidden assumptions page contains the underlying action catalog and research-backed minute ranges.

## Value vs Cost

Value versus Cost compares modeled value with customer-priced observed consumption under the selected billing mode. Read credit bands and value bands separately before using the ratio. Re-run the page with Finance-approved terms and test whether the conclusion survives changes in both cost and value assumptions.

## Value by Department

Value by Department shows how observed tasks, credits, modeled value, and allocated cost distribute across business units. Check identity-match coverage before comparing teams. Differences may reflect population, work mix, consumption, or missing organization data, so pair the page with business context before acting.

## Value by User Tier

Value by User Tier reveals whether activity and modeled value are broadly distributed or concentrated among a smaller group. The percentile split requires at least twenty active users and changes with the filter context. Use it to identify enablement patterns, champions, or dependencies, not to rate employee performance.

## Right-Sizing & Reclaim

Right-Sizing and Reclaim combines observed credits, allowance, activity recency, and budget segments. Near-limit, over-limit, inactive, and low-use flags are review prompts. Confirm role, leave, seasonality, manager context, and contract terms before changing access, allowance, or assignment.

## Skills & Allocated Consumption

Skills and Allocated Consumption uses friendly labels for known skills and readable fallbacks for technical identifiers. Invocations and users are observed. Credits, cost, and classified value are directional allocations because the source does not meter them per skill. Use volume for enablement and allocation only as planning context.

## Model & LLM Breakdown

Model and LLM Breakdown appears only when Purview supplies model attribution. The page can distribute modeled value, cost, and credits by task share, but those fields are not model-specific meters. If model data is unavailable, stop. Obtain source-backed metering before recommending a model on cost or efficiency.

## Metric Glossary

The Metric Glossary is the final quality gate. It defines each metric, its calculation, evidence condition, source dependency, and limitation. When a result leaves the report, carry its definition, reporting period, filters, evidence label, selected assumptions, and owner into the decision record.
